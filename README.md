# ТОМСК МОНОЛИТ

Рабочий сайт производителя бетонной брусчатки и бордюров: Flask, SQLite, Vanilla JavaScript и Three.js без Node.js и сборщика. Все библиотеки, шрифты и модель обслуживаются локально.

## Что реализовано

- Светлая адаптивная главная страница в единой navy/золотистой дизайн-системе, типографика Manrope/Unbounded (локальные WOFF2 с кириллицей) и desktop 3D-сцена: крупная GLB-модель брусчатки с процедурной текстурой натурального бетона (без надписей) и мягкими контактными тенями занимает весь первый экран и поворачивается по прокрутке; в финале поворота рядом с плиткой появляется информация о компании.
- На экранах до 800 px, при отключённом WebGL и при настройке reduced motion показывается лёгкий SVG-постер; Three.js на смартфонах не загружается.
- Два товара, редактируемые описания и цены. Пустая цена выводится как «Стоимость по запросу».
- Два независимых калькулятора (брусчатка и бордюр) с настраиваемыми нормами (брусчатка 50 шт./м², бордюр 1 шт./пог. м), запасом 0–20% только у брусчатки, округлением вверх и переносом результата в заявку.
- Ранний коммерческий блок заявки `#quick-order` размещён сразу после раздела «Ассортимент»; он и короткая форма в окне «Связь» используют общий `/api/orders`, клиентскую и серверную валидацию, CSRF, обязательное согласие и сохранение в SQLite. Обе короткие формы передают `request_type=callback` и не требуют город или количество; основная заявка `#order` требует только контакты, согласие и положительное количество хотя бы одного изделия; поле «Населённый пункт» удалено, адрес необязателен.
- Telegram- и email-уведомления. Если сервисы не настроены или недоступны, заявка всё равно сохраняется; результат виден в карточке заявки.
- Административная панель: заявки и статусы, товары и цены, нормы расхода, доставка, контакты, реквизиты, фотографии.
- Загруженные JPEG/PNG/WebP проверяются через Pillow, уменьшаются и преобразуются в WebP. Максимальный исходный размер — 6 МБ.
- SEO/Open Graph, sitemap, robots, страница политики и адаптивная галерея с клавиатурным управлением.

## 1. Установка и запуск

Требуется Python 3.11 или новее. Blender и Node.js не нужны.

### Windows PowerShell

```powershell
cd tomsk-monolit
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python -m flask --app app init-db
python app.py
```

### Linux / macOS

```bash
cd tomsk-monolit
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python -m flask --app app init-db
python app.py
```

Откройте `http://127.0.0.1:5000`. Режим debug в `app.py` предназначен только для локальной разработки.

База создаётся автоматически при запуске в `instance/monolit.sqlite3`. Фотографии сохраняются в `instance/uploads/`. Не удаляйте папку `instance` при обновлении сайта.

## 2. Настройка администратора

1. В активированном виртуальном окружении выполните:

   ```bash
   python -m flask --app app password-hash
   ```

2. Введите уникальный пароль длиной не менее 12 символов. Команда выведет безопасный хеш Werkzeug.
3. Скопируйте хеш целиком в `ADMIN_PASSWORD_HASH` файла `.env`. Задайте `ADMIN_USERNAME` и длинный случайный `SECRET_KEY`.
4. Перезапустите приложение. Панель доступна по `/admin/login`.

Пароль нигде не сохраняется в открытом виде. Если хеш не задан, вход администратора отключён. Для смены пароля создайте новый хеш и замените переменную.

## 3. Заполнение перед публикацией

Через административную панель заполните:

- цены или оставьте поля цен пустыми;
- телефон, email, адрес, график, мессенджеры и настоящие реквизиты;
- подтверждённый текст о доставке;
- фотографии реальных работ и их подписи.

В `templates/policy.html` замените все квадратные скобки, добавьте данные оператора, сроки хранения и порядок отзыва согласия. Документ должен проверить юрист. Не принимайте реальные заявки, пока контакты оператора и политика не заполнены.

Пока в административной панели не загружены реальные проекты, в блоке «Примеры работ», в карточках продукции и в разделе преимуществ показываются фотографии продукции и объектов из `static/images/works/`, `static/images/product-paver.webp`, `static/images/product-border.webp`; после первой загрузки через панель в галерее показываются только фотографии из панели. Фотография доставки — локальный файл `static/images/delivery-manipulator.webp` (манипулятор выгружает паллеты), фотография производства в разделе преимуществ — `static/images/production-crane.webp`. 3D-модель брусчатки находится в `static/models/concrete-block-natural.glb`. Модель пересобирается из исходного экспорта скриптом `tools_rebuild_glb.py` (процедурные текстуры бетона; флаг `EMBOSS` включает рельефное тиснение «МОНОЛИТ», флаг `MARKING` — плоскую маркировку «МОНОЛИТ» на верхней грани; оба флага по умолчанию выключены, надписей на модели нет).

## 4. Telegram-уведомления

1. Создайте бота через официальный `@BotFather` и получите токен.
2. Добавьте бота в нужный чат или начните с ним диалог.
3. Узнайте ID чата и заполните:

```dotenv
TELEGRAM_BOT_TOKEN=токен_бота
TELEGRAM_CHAT_ID=id_чата
```

Токен используется только на сервере. Не вносите его в JavaScript или шаблоны.

## 5. Email-уведомления

Заполните параметры своего почтового провайдера:

```dotenv
SMTP_HOST=smtp.example.ru
SMTP_PORT=587
SMTP_USERNAME=login
SMTP_PASSWORD=пароль_приложения
SMTP_FROM=sender@example.ru
NOTIFY_EMAIL_TO=orders@example.ru
SMTP_USE_SSL=0
SMTP_USE_TLS=1
```

Для SSL-подключения обычно используется порт 465, `SMTP_USE_SSL=1` и `SMTP_USE_TLS=0`. Рекомендуется отдельный пароль приложения, а не основной пароль почтового ящика.

## 6. Публикация на домене

Ниже — пример для Ubuntu, Nginx и Gunicorn. Архитектура приложения не меняется.

1. Зарегистрируйте домен и направьте A-запись на IP сервера. Загрузите проект, например в `/var/www/tomsk-monolit`.
2. Установите зависимости в виртуальное окружение, создайте `.env`, задайте `COOKIE_SECURE=1`, надёжные `SECRET_KEY` и хеш пароля. Если приложение работает только за настроенным Nginx, добавьте `TRUST_PROXY=1` для корректных HTTPS-ссылок; не включайте этот параметр при прямом доступе к Gunicorn из интернета. Ограничьте доступ к `.env` и `instance` для посторонних пользователей сервера.
3. Проверьте production-запуск:

   ```bash
   . /var/www/tomsk-monolit/.venv/bin/activate
   cd /var/www/tomsk-monolit
   python -m flask --app app init-db
   gunicorn --workers 2 --bind 127.0.0.1:8000 app:app
   ```

4. Настройте systemd для автоматического запуска Gunicorn. Рабочая директория — `/var/www/tomsk-monolit`, команда — `/var/www/tomsk-monolit/.venv/bin/gunicorn --workers 2 --bind 127.0.0.1:8000 app:app`.
5. Настройте Nginx как обратный прокси на `127.0.0.1:8000`, передавайте `Host` и `X-Forwarded-Proto`. Статические файлы можно дополнительно кэшировать средствами Nginx, но не трогайте `instance`.
6. Получите HTTPS-сертификат, например через Certbot, и включите редирект HTTP → HTTPS. После проверки HTTPS оставьте `COOKIE_SECURE=1`.
7. В панели заполните контент, отправьте тестовую заявку и проверьте Telegram/email. Удалите тестовую заявку через базу только при необходимости; в интерфейсе её можно перевести в «Отменена».

Не используйте `python app.py` или Flask development server как публичный production-сервер.

## 7. Резервное копирование и обновление

Регулярно копируйте `instance/monolit.sqlite3` и `instance/uploads/`. На время консистентной резервной копии SQLite используйте штатный backup-механизм SQLite или остановите запись. При обновлении сохраните `.env`, `instance/`, затем замените код и перезапустите Gunicorn.

## Структура

```text
tomsk-monolit/
├── app.py                 # маршруты, заявки, админ-панель, уведомления
├── config.py              # переменные окружения и безопасные настройки
├── database/schema.sql
├── instance/              # SQLite и загрузки; не публикуется как статика
├── templates/             # страницы и административные шаблоны
└── static/
    ├── css/               # сайт и административная панель
    ├── js/                # main, three-scene, calculator, form, gallery
    ├── js/vendor/         # локальные Three.js и addons
    ├── models/            # GLB-модель брусчатки без надписей
    ├── images/            # иллюстрации, постер, OG, favicon
    └── fonts/             # локальные Manrope/Unbounded WOFF2
```

## Публикация на Render (бесплатно)

1. Создайте аккаунт на [render.com](https://render.com) и войдите через GitHub.
2. **New → Web Service → Connect repository** → выберите `delicvova95-glitch/Monolit-`.
3. Render подхватит `render.yaml`: сборка `pip install -r requirements.txt`, запуск Gunicorn, автогенерация `SECRET_KEY` — менять ничего не нужно, нажмите **Deploy**.
4. Через несколько минут сайт получит публичный адрес вида `https://tomsk-monolit.onrender.com`.
5. В **Settings → Environment** при желании задайте Telegram/SMTP-переменные из `.env.example`.
6. Каждый `git push` в `main` автоматически обновляет сайт.

База SQLite создаётся автоматически при первом запуске (`database/schema.sql`).
